# 155. The source for the player's own SideStore is at source.cartouche.cloud

2026-11-24

The source a player adds to their own SideStore to install Cartouche without a computer ([decision 147](147.md)) is at **https://source.cartouche.cloud/**, a name of the project's domain, rather than at its address on raw.githubusercontent.com.

- The [Showcase site](../../.github/workflows/site.yml) workflow publishes [`app/sidestore-player-source.json`](../../app/sidestore-player-source.json) on GitHub Pages, beside the site, as **https://cartouche.cloud/sidestore.json**, and again each time that file changes on main: merging the Release workflow's *Source* pull request publishes each new version within minutes. The file stays where it is, the one the Release workflow writes, so its address on raw.githubusercontent.com keeps giving the same source.
- GitHub Pages serves one domain for a repository, so a name under the domain cannot be the site's. The Cloudflare Worker `cartouche-source` ([`source/`](../../source/README.md)) answers at `source.cartouche.cloud` with that file as Pages has it, kept five minutes in Cloudflare's cache, and nothing else. The site workflow deploys it in the account that has the zone, since a Worker's domain is in the account of its zone, with the Domain workflow's token *Cartouche domain*, to which the owner added **Account › Workers Scripts › Edit** and **Zone › Workers Routes › Edit**; it attaches `source.cartouche.cloud` itself, and Cloudflare keeps that name's DNS record, outside [`domain/records.json`](../../domain/records.json), as for `build.cartouche.cloud`. The first deploy took the telemetry's token, whose account is the owner's own: each deploy removes the copy it left there.
- [`app/config.env`](../../app/config.env) gives the IPA for the player's SideStore ([`sidestore_ipa.py`](../../app/scripts/sidestore_ipa.py)) the Pages address, `CARTOUCHE_PLAYER_SIDESTORE_SOURCE_URL`, where Cartouche installed from it and its built-in SideStore read their updates: the same file, with no Worker in between, so its updates hang on GitHub Pages alone. No release has listed that IPA yet: the first one carries that address, and no iPhone has the old one.

The page does not link to the source. The site's tests check that the address in `app/config.env` is the site's, that the workflow publishes the file there, runs when it changes and deploys the Worker outside the Full test pass, that the Worker reads that address, and that the source lists Cartouche alone, its IPA for the player's SideStore from this repository's releases: never a game ([`site/tests/test_site.py`](../../site/tests/test_site.py), [`source/test/`](../../source/test/)).

The source the built-in SideStore of every other IPA reads, [`app/sidestore-source.json`](../../app/sidestore-source.json), stays at its address: every Cartouche installed reads its updates there.

**Why.** Ad asked on 24 November 2026 whether the source for SideStore could go through a Cartouche domain name, then for `source.cartouche.cloud` rather than `cartouche.cloud/sidestore.json`: a player types or pastes that address into their SideStore, and a name of its own at the project's domain is short, says whose it is, and does not hang on where the repository lives.
