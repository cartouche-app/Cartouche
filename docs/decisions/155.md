# 155. The source for the player's own SideStore is at cartouche.cloud

2026-11-24

The source a player adds to their own SideStore to install Cartouche without a computer ([decision 147](147.md)) is at **https://cartouche.cloud/sidestore.json**, the project's domain, rather than at its address on raw.githubusercontent.com. The [Showcase site](../../.github/workflows/site.yml) workflow publishes [`app/sidestore-player-source.json`](../../app/sidestore-player-source.json) there with the site, on GitHub Pages, and again each time that file changes on main: merging the Release workflow's *Source* pull request publishes each new version within minutes. The file stays where it is, the one the Release workflow writes, so its address on raw.githubusercontent.com keeps giving the same source.

[`app/config.env`](../../app/config.env) gives that address, `CARTOUCHE_PLAYER_SIDESTORE_SOURCE_URL`, to the IPA for the player's SideStore ([`sidestore_ipa.py`](../../app/scripts/sidestore_ipa.py)), so Cartouche installed from it, and its built-in SideStore, read their updates there too. No release has listed that IPA yet: the first one carries the new address, and no iPhone has the old one. The domain's records do not change: the site's already point to GitHub Pages ([domain/README.md](../../domain/README.md)). The page itself does not link to the source.

The site's tests check that the address in `app/config.env` is the site's, that the workflow publishes the file there and runs when it changes, and that the source lists Cartouche alone, its IPA for the player's SideStore from this repository's releases: never a game ([`site/tests/test_site.py`](../../site/tests/test_site.py)).

The source the built-in SideStore of every other IPA reads, [`app/sidestore-source.json`](../../app/sidestore-source.json), stays at its address: every Cartouche installed reads its updates there.

**Why.** Ad asked on 24 November 2026 whether the source for SideStore could go through a cartouche domain name: a player types or pastes that address into their SideStore, and one at the project's domain is short, says whose it is, and does not hang on where the repository lives.
