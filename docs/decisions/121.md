# 121. Without LiveProcess in the app, Cartouche says to install it again over itself, and stops renewing itself

2026-11-15

When LiveContainer's LiveProcess extension, which the built-in SideStore runs in, is missing from the app, LiveContainer's bridge cannot start SideStore, and a sign-in, a renewal or an update of Cartouche fails at once. Cartouche then says what to do in its own words, in English and in French, in the place of LiveContainer's: install Cartouche again over this copy with the Cartouche Installer, on the computer, with the same Apple ID, which puts LiveProcess back and keeps the games and saves (`CartoucheRenewalTrouble.liveProcessMissing`, `CartoucheSignInMessage.Trouble.noLiveProcess`, `CartoucheText.noLiveProcess`). The update's notice shows these words alone, without its sentence that says to check LocalDevVPN and try again. Cartouche no longer renews itself while LiveProcess is missing, which it looks for where LiveContainer's bridge does, in the app's own PlugIns (`CartoucheLiveProcess`), and the System page says it under **Renew now**, which stays and says the same. Nothing else is held back: an update, a sign-in or **Renew now** tried anyway fails with these words.

This amends [decision 88](../decisions.md): the renewal Cartouche starts by itself also waits for LiveProcess in the app, as it waits for a certificate Apple has not revoked ([decision 116](116.md)).

**Why.** In the measurements of November 15, a copy of 0.12.1 tried its update to 0.13.0 11 times, each failing with `liveProcessMissing`: its notice said each time to check LocalDevVPN and try again, then gave LiveContainer's words, in English, which send the player to the settings of "LiveContainer+SideStore", of SideStore and of PlumeImpactor, none of which a player of Cartouche uses. Nothing in Cartouche can put an extension back in a signed app: only an install of Cartouche over itself, which the Cartouche Installer makes with every extension, as it signs them with Cartouche's own profile ([decision 105](../decisions.md)). How that copy lost LiveProcess is not known: an install by another tool that removed the app's extensions would leave it so. The renewal Cartouche starts by itself in its last 3 days ([decision 98](098.md)) would fail the same way every 6 hours, opening LocalDevVPN for each try, until the signature expired. Holding back only that renewal, and not what the player starts, keeps a wrong reading of the app's PlugIns from ever stopping an update or a sign-in. A LiveProcess that is there but does not start (`liveProcessFailed`, 2 renewals by November 15) is another trouble, which keeps LiveContainer's words until it is understood.
