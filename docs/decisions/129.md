# 129. Cartouche has a Discord server, set up by its bot from a private repository, and the site and the README link to it

2026-11-17

Cartouche's players have a Discord server, *Cartouche*, in English, with a corner each in French, Spanish and German, a channel to talk and a help forum, which a member sees by picking the language as they join: the news of each version, a FAQ, help forums for the iPhone and iPad and for the Mac, and suggestions. Its rules, in the four languages, are the project's own (1): nobody shares, asks for or points to games, IPAs built from games, keys or firmware, nor posts an address of a server or of storage, an Apple account or a password. AutoMod blocks links to file hosts and piracy sites, requests for games, IPAs or keys, and addresses of servers and storage, in the four languages. The owner created the server and its bot, the application *Cartouche*, since Discord no longer lets an application create a server; everything else, the roles, channels and permissions, the messages, AutoMod, onboarding and the server's one permanent invite, is written down in a private repository and applied by the bot from a workflow there, never by hand. The site, in its header beside GitHub, in its footer and in the FAQ's answer on help, its download page and the README link to the server by that invite, <https://discord.gg/wG3DZjdAeF>, which `site/tests` checks is the pages' only Discord address. It amends [decision 40](../decisions.md): the site links to Cartouche's Discord server too.

**Why.** The owner asked for a clean Discord server for Cartouche, then for corners in Spanish and German beside the French one (2026-11-17), and chose to open it by an invite, on the site and in the README. Help that a player can ask for in their language, and see answered for others, takes less of everyone's time than issues alone, which stay where bugs go. AutoMod's lists work only while nobody can read them, and the bot's token stays a secret of that private repository. An invite that never expires gives the same link everywhere: the bot keeps it, and finds it again at each run rather than making another.
