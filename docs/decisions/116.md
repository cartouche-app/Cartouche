# 116. On a certificate Apple revoked, Cartouche says to install it again over itself, and stops renewing itself on it

2026-11-15

When a renewal or an update of Cartouche by the built-in SideStore fails because Apple revoked the certificate of Cartouche's signature (SideStore's `certificateRevoked`, at its `VerifyCertificate` step), Cartouche says what to do in its own words: install Cartouche again over this copy with the Cartouche Installer, on the computer, with the same Apple ID, which keeps the games and saves. It no longer renews itself on that signature: it notes when the signature expires, and renews itself again once an install has given it another ([`CartoucheRenewalRules.swift`](../../launcher/Sources/CartoucheRenewalRules.swift), `CartoucheRenewals` in [`CartoucheRenewal.swift`](../../launcher/Sources/CartoucheRenewal.swift)). Until then, the System page says it under **Renew now**, which stays. Cartouche does not sign in again for it. When SideStore did not reach this iPhone, a renewal and an update say what to do as the sign-in does (`CartoucheText.deviceMessage`): connect LocalDevVPN, join a Wi-Fi network, put the pairing file in Cartouche again. The update's notice then shows these words alone, without its sentence that says to check LocalDevVPN and try again before SideStore's words.

This amends [decision 88](../decisions.md): the renewal Cartouche starts by itself also waits for a signature whose certificate Apple has not revoked.

**Why.** In the measurements of November 13 and 14, 4 renewals of 3 copies of 0.12.x failed so: SideStore no longer found the certificate among the account's, and Apple's OCSP answered that it was revoked, while LiveContainer's check still found it working, so that nothing told the player what to do. Most likely another app or computer took a new certificate with the same Apple ID. A renewal signs nothing again, so it cannot change that, and from 0.13.0 Cartouche would have tried again every 6 hours, opening LocalDevVPN for each try ([decision 98](098.md)), until the signature expired and iOS no longer opened Cartouche. Nor can a new sign-in: the built-in SideStore never revokes the certificate of another installation, nor makes a new one while the account has one ([`0004`](../../app/patches/sidestore/0004-never-revoke-a-certificate.patch), [`0012`](../../app/patches/sidestore/0012-find-the-certificate-a-computer-left-in-the-app.patch)), and stops on "This Apple account already has a certificate". Only an install of Cartouche over itself, which signs it anew, gives it a working certificate; the same Apple ID keeps the same team, so the same app and its data. The signature's expiry date tells that install apart, without a new key in the Info.plist or the keychain. Up to 0.13.0, a renewal and an update that did not reach this iPhone showed SideStore's words, which send the player to SideStore's own settings, while the sign-in already said what to do.
