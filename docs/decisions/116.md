# 116. A copy of Cartouche Builder already installed finds every release

2026-11-15

Cartouche Builder reads GitHub's answers to its releases one after the other, a hundred releases each, until one has a release of the builder's, ten answers at most, rather than the forty newest releases alone ([`Updater.swift`](../../builder/mac/Sources/BuilderKit/Updater.swift)). What a copy already installed looks for is what every release publishes, and stays so: the tag `builder-v<version>`, the disk image `Cartouche-Builder-<version>.dmg` with its SHA-256 beside it, neither a draft nor a pre-release, an app whose bundle identifier is `io.github.clabeuhtegrite.cartouche-builder`, from the releases of `cartouche-app/Cartouche` or of the repository GitHub answers for once it moved. Renaming the app, its disk image or its tag, as Cartouche Builder renamed Cartouche will ([roadmap](../roadmap.md)), means publishing these names as well, for as long as such copies run; the bundle identifier never changes ([`test_updates.py`](../../builder/tests/test_updates.py)). The app's tests update an installed copy from end to end, from releases they serve as GitHub does, and the **Builder** workflow does it again with the disk image it made, before anything is published ([`UpdaterEndToEndTests.swift`](../../builder/mac/Tests/BuilderKitTests/UpdaterEndToEndTests.swift)). Copies of 0.5.0 and older are downloaded again once, by hand.

**Why.** Ad, 2026-11-15, as Cartouche Builder 0.6.0 came out: the Builders already installed must update themselves without going through the site. Those of 0.5.0 and older cannot, and nothing published can reach them: they take a disk image only from an address under `github.com/clabeuhtegrite/Cartouche/releases/download/`, and since the repository moved ([decision 111](111.md)) GitHub gives every file of its releases under `cartouche-app/Cartouche`, whatever address it is asked at. Only a repository made again at the old address would give them the old one, and it would end the redirects through which every iPhone and every Installer given out updates. The rest of what they read, the telemetry server's answers and the list of covers, carries no update. So that it does not happen again: Cartouche's releases and its Installer's, two at each version of Cartouche, every two days, would push the builder's newest release out of the forty after a few weeks without one of the builder's, and every copy would then say it is up to date; and a change to a name the copies look for would leave them all behind in the same way, which the tests now refuse before it merges.
