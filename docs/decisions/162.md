# 162. The player's Mac reads a game of the NAS on its Ethernet for the iPhone plugged into it

2026-11-25

With the iPhone plugged into the player's Mac by its cable ([decision 143](143.md)), a game of a games folder on a NAS's shared folder, an FTP or an SFTP server comes through the Mac when the Mac reaches that server on its Ethernet: Cartouche Builder reads it there, through the player's connection as the console keeps it, the same as the iPhone's since [decision 125](125.md), signed in to as the iPhone signs in, by the iPhone's own code ([`ConsoleRelay.swift`](../../builder/mac/Sources/CartoucheConsole/Mac/ConsoleRelay.swift)), a piece ahead, so that the next piece comes from the NAS while one goes through the cable, and passes it on ([`BridgeRelay.swift`](../../builder/mac/Sources/BuilderKit/BridgeRelay.swift)). The player sets nothing: Cartouche asks the Mac first as an install opens the file, and each time it opens it again after a break ([`CartoucheStorageMac.swift`](../../launcher/Sources/CartoucheStorageMac.swift)); a Mac that refuses, or fails on the way, leaves the iPhone reading the NAS itself, as before.

The Mac refuses on its Wi-Fi, the game crossing the Wi-Fi all the same: it tells the way by opening a connection to the server's host and port, within three seconds, and reading the interface it leaves by ([`BridgeNetwork.route`](../../builder/mac/Sources/BuilderKit/BridgeNetwork.swift)), each time a file is opened. It reads only a file of the games folders it keeps on that connection, the games folder and the others the iPhone reads, never a saves folder nor anything else of the place; never a bucket nor a Google Drive, which the internet brings to the iPhone as fast either way ([`CartoucheCableRelay`](../../launcher/Sources/CartoucheBridgeCable.swift), one file on both sides). Only through the cable: the bridge's info says `relays` to a session that came by the cable from a Cartouche Builder with the console, and the Mac denies `relayStat` and `relayRead` to one of the network; Cartouche for Mac 0.8.0 and older, which end a session on an operation they do not know, are never asked. A session keeps two files open at most, an IPA and the image of its game files, all closed when it ends.

The install's screen says **By cable, through the Mac**, with no advice under it ([decision 151](151.md)); `game.installed` and an install's `error` carry `link` `relay`, their `from` still the kind of the server ([telemetry/README.md](../../telemetry/README.md)), and the install's report says so. The Builder's iPhone page shows how fast it sends, as for a game of its own games folder. Cartouche's console on the Mac installs no game over a connection, so the iPhone alone asks. None of it has been tried on a real Mac, NAS and iPhone yet, nor the speed the cable gives measured.

**Why.** A contributor reads a library of about 290 GB, games of 25 to 33 GB, on a Synology through the iPhone's Wi-Fi at 10 to 12 MB/s, while their Mac mini, on a gigabit Ethernet, has the iPhone plugged into it ([#323](https://github.com/cartouche-app/Cartouche/issues/323), 2026-11-25). Ad (2026-11-25): only when the Mac is on Ethernet; a MacBook on its Wi-Fi would gain nothing. The Mac already has the player's connections and the folders chosen on the iPhone, so the relay needs no setting, and the iPhone's own reading stays the way back whenever the Mac cannot.
