# 168. Keep other apps' sound: a game's sound can play over the player's music or podcast on the iPhone, off until they turn it on

2026-11-26

**System › While a game runs › Keep other apps' sound** lets the music or podcast the player plays in another app go on under a game's sound. It is off until the player turns it on, and off, nothing changes: the game's sound stops other apps' sound as it starts, as before. It takes effect from the game's next start. A game paused behind the console keeps what it started with.

nxnative's iOS front end sets the game's audio session to the Playback category, without options (`front_ios.m`, `front_ios_audio_session`). A session of that category that does not mix stops other apps' sound as it becomes active. nxnative sets it at the game's start, as the game comes back to the front, after an interruption and after iOS resets its media services. Cartouche does not change nxnative. Its own code in the game's process, which LiveContainerShared loads in every game behind the console and in Cartouche's place ([`launcher/Guest/CartoucheOtherAudioSession.m`](../../launcher/Guest/CartoucheOtherAudioSession.m)), sets every category the game sets with `AVAudioSessionCategoryOptionMixWithOthers` too, however the game sets it, for the categories that take that option: Playback, PlayAndRecord and MultiRoute. A category set before that code runs is set again with the option. That code finds AVAudioSession at run time and links neither AVFAudio nor UIKit, which LiveContainerShared would load in every process of Cartouche's, the built-in SideStore's included. It acts only in nxnative's games.

As Play starts a game, Cartouche writes the player's choice in the game's data folder, `Library/Cartouche/OtherAudio.plist` ([`CartoucheOtherAudio.swift`](../../launcher/Sources/CartoucheOtherAudio.swift)), and removes the file while the setting is off. The code in the game's process reads it as the game has finished launching, before the game's first scene, where nxnative sets its session.

What does not change: the Playback category plays on silent, mixing or not; the game's sound goes where iOS sends every app's sound, to a TV by cable or AirPlay too; a call, Siri or an alarm interrupts the game's sound as it interrupts other apps', and nxnative sets the session again once it ends. No entitlement, no extension and no Info.plist key is added.

The Mac needs nothing: macOS plays every app's sound together, and nxnative plays through the Mac's default output, as any app does, without taking the device for itself (`hle_audio.c`, `kAudioUnitSubType_DefaultOutput`). The Mac has no such setting.

The game measurements say, for each session on the iPhone, whether the game kept other apps' sound (`otherAudio`, [telemetry/README.md](../../telemetry/README.md#reports)), as the file in its data folder says when Cartouche reads the session's log.

The launcher's harness runs the code that mixes with the Simulator's AVAudioSession (`OtherAudioTests`), and checks what Play writes (`PlayTests`). None of it has been tried on a real iPhone yet.

**Why.** A game of Cartouche's stopped the player's music or podcast, which other front ends of nxnative already let play on. Off by default, so that a game sounds as nxnative meant it, and nobody hears two sounds at once without having asked for it (Ad, 26 November 2026: "On fait tout").
