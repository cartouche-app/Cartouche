# 120. On the Mac, the console keeps a game's settings, its language and its play time, and says how it fits, as on the iPhone

2026-11-15

**Game settings**, on a game's sheet in Cartouche's console on the Mac, opens the iPhone's settings page in place of the sheet, the way back to the sheet above it, the controller's L and R changing the section and B going back, as on the iPhone ([`ConsoleSettings.swift`](../../builder/mac/Sources/CartoucheConsole/Mac/ConsoleSettings.swift)). Its rows are those nxnative lists in the game's app, `Contents/Resources/dm/launcher.json`, the Mac's own among them, **Display mode** and **Switch 2 controllers**. Each choice goes where nxnative's app reads it at every start, from Cartouche, the Finder or the Dock: the app's preferences domain (`launcher.<variable>`), a choice equal to the game's default removed, so that nxnative's settings window is no longer needed; the page's last button still starts the game on it. A setting the player's `env.txt` (in nxnative's folder of the game) or the app's own sets shows fixed. **Display mode** shows Fullscreen as its default, as Cartouche starts its games filling the screen ([decision 114](114.md)), and a window chosen there is kept as nxnative's `0`. The game's language follows the Mac's when the game has it, by the iPhone's rule (`CartoucheGameLanguage`, which `CartoucheCore` now shares with the builder): its first option says the Mac's language, and the builder chooses it again before each start it makes, unless the player chose one, in the console or in nxnative's window, or the start or an env file sets it ([`MacPlay.swift`](../../builder/mac/Sources/BuilderKit/MacPlay.swift)); a game that has none of the Mac's languages starts in the games' language of the builder's settings. The play time on the sheet is the time the game's app is the Mac's active one, which the builder counts while it runs, wherever the game was started: a session for each run that came to the front, written when it leaves the front and every 30 seconds, nothing while the Mac sleeps, its screen is locked or another session is in front, in the file the iPhone's counter writes, `Library/Cartouche/PlayTime.plist` in nxnative's folder of the game, which the console reads as the iPhone's does ([`MacPlayTime.swift`](../../builder/mac/Sources/BuilderKit/MacPlayTime.swift)). The sheet says how the game fits this Mac by the iPhone's rule (`CartoucheGameFit`): an Apple chip and the macOS its app needs, 26.6 for nxnative's, the testers' results on this Mac's model, and the memory Metal lets a game use here, Increased Memory Limit being iOS's alone. **Edit the game's info** opens over the console, as on the iPhone. The console names the games' languages, and writes its numbers and days, in the language it speaks, which the builder's settings may choose other than the Mac's. The Builder's gallery shows the settings page, the info editor and the whole sheet of a game played on the Mac, its games' play times and sizes its own, nothing of the player's read or kept. This is the sixth step of [decision 95](095.md). None of it has been tried on a real Mac yet.

**Why.** Ad asked for the whole of the iPhone's app on the Mac, with each of its changes (2026-11-13): the settings page, the language of the games, the play time and the fit were the iPhone's alone, and **Game settings** on the Mac made the player go through nxnative's window before a game. nxnative's apps for the Mac read the choices saved in their own preferences at every start (its `docs/frontends.md`, "Saved choices"), so that one page serves a start from Cartouche, the Finder and the Dock alike. Fullscreen is how Cartouche starts a game on the Mac, where nxnative's default is a window, which nxnative never saves: a page that showed nxnative's default would say Window for a game that fills the screen. On the iPhone, a counter in the game's process counts its play time; nothing of Cartouche's runs in the process of a game on the Mac, while the builder follows each game's app from its start to its end, and knows which app is in front. The iPhone's file and format let the console read the time as it reads the iPhone's, and Mac and iPhone count the same thing: the time a game is in front and active. The Mac's uptime stops while it sleeps, so a game left open overnight adds nothing.
