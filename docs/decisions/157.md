# 157. The players' problems go to the organization's cartouche-reports

2026-11-24

The private repository the telemetry server files the players' problems in ([decision 36](../decisions.md)), with the Discord server's bot and its workflows, moves from Ad's account to the organization: `clabeuhtegrite/cartouche-reports` becomes **`cartouche-app/cartouche-reports`**, still private. Ad moves it from its settings (Transfer); GitHub keeps its issues, branches and the bot's secret, and redirects its old name. No repository is made again at the old name, which would end those redirects.

- The [Telemetry](../../.github/workflows/telemetry.yml) workflow names `cartouche-app/cartouche-reports` when the variable `CARTOUCHE_REPORTS_REPOSITORY` is not set. Its secret `CARTOUCHE_REPORTS_TOKEN` is a fine-grained token whose resource owner is the organization, for that repository alone, with **Issues › Read and write** ([telemetry/README.md](../../telemetry/README.md#deploy)): a token of Ad's account cannot reach a repository the organization owns, so the one made for the old place is replaced, and deleted.
- [`deploy.sh`](../../telemetry/deploy.sh) follows GitHub's redirect when it checks that the repository is private, and binds the Worker and the dashboard to the name GitHub answers with: a variable left at the old name still files the problems where they are.
- Until the deploy with the new token, the server keeps the problems players send, as it does whenever GitHub refuses one, and its daily run files them.

It amends [decision 111](111.md), where the repository stayed on Ad's account.

**Why.** Ad wants everything of Cartouche in its organization (2026-11-24), where its backup and mirror take it with the rest. The bot and the problems keep working from there, and the issues the server files keep coming from Ad's account, whose token it is.
