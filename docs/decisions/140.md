# 140. On an expired Apple session, Cartouche signs in again by itself once, then renews itself, and Sign in again shows only when it is needed

2026-11-24

When a renewal or an update of Cartouche by the built-in SideStore fails because Apple said that the session SideStore asks it with has expired (Apple's -1 and "Your session has expired", or 1100, at SideStore's `VerifyCertificate` step: `CartoucheRenewalTrouble.sessionExpired`), Cartouche notes the signature it has then, and no longer renews itself on it (`CartoucheAutomaticRenewal.Wait.sessionExpired`, in [`CartoucheRenewalRules.swift`](../../launcher/Sources/CartoucheRenewalRules.swift)). After the renewal it started by itself that found it, with LocalDevVPN connected, it signs in again by itself, with the Apple ID and password SideStore keeps, once for that signature (`CartoucheExpiredSession.signsInAgain`): the player sees that sign-in only should Apple ask for a code. As soon as a sign-in goes through, by itself or the player's, Cartouche forgets the note and renews itself at once ([`CartoucheRenewal.swift`](../../launcher/Sources/CartoucheRenewal.swift), `signedIn`). A renewal, an update or an install over Cartouche that goes through forgets it too.

Until then, the System page says so in Cartouche's own words, in English and in French, with **Sign in again** under them, and its Setup row is to do; in the setup, the Apple ID step is to do again, with **Sign in again**. Otherwise **Sign in again** shows in the setup only when something is left to do: no Apple ID, no certificate, a certificate refused, or this iPhone to register.

This amends [decision 88](../decisions.md): the renewal Cartouche starts by itself also waits for a session Apple has not said expired, as it waits for a certificate Apple has not revoked ([decision 116](116.md)) and for LiveProcess ([decision 121](121.md)).

**Why.** From November 19 to 24, the measurements show 54 renewals and updates of 7 copies, from 0.13.1 to 0.15.1, failing at `VerifyCertificate` with Apple's -1 and "Your session has expired": the System page and the update's notice showed SideStore's words, and Cartouche tried again every 6 hours in the last 3 days, opening LocalDevVPN for each try ([decision 98](098.md)), each failing the same way. SideStore renews with the token of its last sign-in and never signs in again by itself, so that only a sign-in gives it a new session: the one copy whose player signed in again went past that step on its next renewal, while an install over Cartouche did not always mend it. Ad's pull request [#283](https://github.com/cartouche-app/Cartouche/pull/283) kept **Sign in again** in the setup at all times; Apple limits sign-ins and may ask for a code each time, so that a button always there would invite sign-ins that change nothing on a copy that works, and a player whose copy failed would still have to find it. Signing in again once by itself, with what SideStore already keeps, mends most copies without the player; once only for a signature, so that a sign-in that fails, or a code nobody types, does not come back at each launch.
