# 144. A game's saves go to the saves folder a few seconds after it saves, while it plays

2026-11-24

While a game plays behind the console on the iPhone, Cartouche beside it, and while a game plays on the Mac, its saves are looked at every 2 seconds, and go to the player's saves folder once they have stayed as they are for 5 seconds since they last changed, or a minute after they first changed for a game that never stops saving ([`CartoucheSaveWatch`](../../launcher/Sources/CartoucheSaveSync.swift)). They go from a copy of `save/` and `save_device/` made at one moment, a clone on an APFS disk, with the files' dates kept (`CartoucheSaveSync.snapshot`): it is made again, three times at most, until the saves did not change while it was made, and when they kept changing, nothing goes until they stop. The game is never paused or waited for, and a save it is writing never goes half written.

Each copy that goes while a game plays takes the place of the one that went before it in the same game, the one after the game too, as long as it is still the newest copy in the folder: one copy for each game, as before, not one for each save, and a copy another iPhone or a Mac sent meanwhile is never replaced. The newest saves still win, and a sync never fetches while the game plays.

When the saves folder's server does not answer, nothing changes from before: the saves wait, and go after the game, or as soon as the server answers again; a sync that fails is tried again a minute later, or as soon as the saves change. When Cartouche leaves the screen while a game plays beside it, what was waiting goes at once. A game that starts in Cartouche's place, Cartouche's own code not running while it plays, still sends its saves when Cartouche comes back. This amends [decision 51](../decisions.md).

Amended by [164](164.md): the saves that go and come hold the game's other profiles and their registry, with the sizes the game gave them, and the list of the shaders it prepared goes beside them.

**Why.** Asked for on 24 November 2026: the saves should go as the game makes them, rather than at the end of the game, whenever the storage can be reached. A game that iOS stops, an iPhone whose battery runs out or a player who switches to another iPhone mid-game then finds the saves of the game, not those of the game before. nxnative commits a game's saves by swapping each of their folders whole (`dm/host/hle_fs.c`, `renamex_np`), so that a folder read during a swap could mix two saves, and a game often saves several times in a row: nxnative's own cloud sender waits 3 seconds for it to stop (`QUIET_MS`). Replacing the game's own copy keeps the ten copies of the folder ten games, which a player picks from to put one back.
