# 171. A `.nup` without DLC of its own is built with the images of its DLC from an `aoc` folder beside it; an IPA built with its game files apart brings its DLC and its other programs in its app

2026-11-26

Cartouche Builder builds a `.nup` that holds no DLC of its own with the images of its DLC the player keeps in a folder named `aoc` beside it, in the game's folder: `1.img`, `2.img`…, each the image of a DLC's files (DMROMFS1), named by the DLC's number, 1 to 2000, as nxnative names a DLC in a build folder and in an app ([`library.py`](../../builder/cartouche_builder/library.py)). The Builder hands them to nxnative's `--aoc-dir` (nxnative PR #2905, 21 November 2026) for the game's IPA and for its app for this Mac, from a folder of links to them alone, each named as nxnative wants it (`1.img`, whatever its letter case), outside the game's build folder, as nxnative asks, since it stages them in there ([`workspace.py`](../../builder/cartouche_builder/workspace.py), `link_aoc`). The images stay where they are. A new image in the folder builds the game again, as a new update or DLC does ("Other files in its folder"); a `.nup` without an `aoc` folder is built as before, from the same fingerprint.

What the Builder leaves out, its library says: an `aoc` folder that is not beside one `.nup` alone (beside several, beside packages or a dump, or with no game at all); images beside a `.nup` that holds DLC of its own, which nxnative builds instead and with which it refuses `--aoc-dir`; a name that is not a DLC's number (`01.img`, `2001.img`, `Pass.img`); one number twice (`1.img` and `1.IMG`, on a drive that tells letter case); a file whose header is not that of a whole image. The folder's other files (a note, the `._` files a drive that is not a Mac's keeps) are passed over, as nxnative passes them over. A folder named `aoc` that holds no image is looked through as any other folder. A checkout of nxnative from before `--aoc-dir` (a commit the Builder falls back to) builds the game without them, and the build's messages say so.

Nothing changes for an IPA built with its game files apart ([decision 68](../decisions.md)): nxnative leaves out of its app the image of the game's own files alone. Its DLC, `aoc/<index>.img`, and the files of the game's other programs, `romfs_programs/<index>.img` (a Switch 2 Edition's Switch 1 program, from a `.nup`), stay in its app, with its files apart as without (`dm/ios/tools/build_ipa.sh`), and Cartouche installs them with it, as it installs the rest of the app; a new build of the game brings its own. nxnative's game reads `Documents/aoc` before `<App>/aoc`, a folder only nxnative's own script for developers writes, from a Mac with the iPhone plugged in (`scripts/push_romfs.sh`, for a project prepared for Xcode); Cartouche writes none, and looks for no DLC or program beside the IPA. The launcher's harness installs such a game from the games folder, then a new build of it (`GameFilesApartTests`).

Cartouche Cloud is not changed by this. No entitlement, no extension and no Info.plist key is added. None of it has been tried on a real Mac or iPhone.

**Why.** nxnative takes the DLC of a `.nup` from elsewhere since 21 November (Pokopia's marker DLC, which unlocks data in its update), and the Builder had no way to give them. A folder beside the `.nup` is how the Builder already finds a game's update and DLC: beside the game, with no setting to set (Ad, 26 November 2026: "Toutes les six").
