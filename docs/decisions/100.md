# 100. What to do when a sign-in stops at its device check, by why minimuxer could not reach the iPhone

2026-11-14

When a sign-in stops at its device check, Cartouche tells the player what to do from why minimuxer could not reach the iPhone, which [patch 0022](../../app/patches/sidestore/0022-tell-cartouche-why-minimuxer-could-not-reach-the-iphone.patch) names ([`CartoucheSignInMessage.swift`](../../launcher/Sources/CartoucheSignInMessage.swift)): for a pairing file the iPhone refused, at the handshake, by its services or by lockdown, delete the pairing the Cartouche Installer stored, choose the iPhone again, put the pairing file in Cartouche again and tap Trust on the iPhone; for a Lockdown pairing file without an IPsec interface, from iOS 26.4, put the pairing file in Cartouche again, which the Installer makes of the newer kind; for an iPhone that does not answer through LocalDevVPN while Cartouche sees it connected, connect LocalDevVPN again, and restart the iPhone should it happen again. The System page tells a copy not set up yet that it can install an update from a computer with the Cartouche Installer, over itself, keeping its games and saves.

**Why.** The sign-in said LocalDevVPN was not connected, under the card that says it is, or to put the pairing file in Cartouche again whatever minimuxer found, and the built-in SideStore never read a pairing file put in place again before [patch 0023](../../app/patches/sidestore/0023-take-a-pairing-file-put-in-place-after-the-first-one.patch). Each of minimuxer's errors has more than one cause, and only some are the player's to fix: the words follow what the player can do about each. A copy that never signed in to Apple cannot update itself, and only the Installer reaches it.
