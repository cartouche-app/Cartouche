# 179. nxnative's prompt that waits for more players and its gear menu, in the language Cartouche speaks on the iPhone too

2026-11-27

nxnative writes its own prompts and menu over a game in English, and takes them in another language from its front end, in the game's environment ([its docs/frontends.md](https://github.com/seedds/nxnative/blob/main/docs/frontends.md#starting-a-game), "Starting a game"; `docs/env_switches.tsv`). Since 24 November 2026, the Mac starts its games with two of them in French, Spanish or German: the Home button's quit prompt (`DM_HOME_QUIT_TEXT`) and the prompt that waits when a game asks for more players than have joined (`DM_CTRL_PROMPT_TEXT`). The iPhone gave its games none: whatever Cartouche spoke, both of the iPhone's were in English, as 249 sessions in French saw them up to 26 November.

On the iPhone, nxnative has two of them: the prompt that waits for more players (`DmGamepad.m`), and the gear menu over the game, four labels (`DM_GAME_MENU_TEXT`, `GameMenu.swift`, from nxnative's commit 90edd532 of 23 November 2026; a game built before shows it in English). Its Home button's quit prompt is the Mac's alone: on the iPhone, Home shows Cartouche's console.

One table of the texts, [`launcher/Sources/CartoucheGameTexts.swift`](../../launcher/Sources/CartoucheGameTexts.swift), in CartoucheCore: the Mac's start of a game (`MacPlayEnvironment.texts`, builder/mac) reads it too, so both say the same words, the Mac's own unchanged. English stays nxnative's, but for the gear menu's title, which says where the other settings are: nxnative's says its start screen, which **Play** skips, so Cartouche names its own **Game settings**, in each language ("More settings in Cartouche: Game settings"). The menu's other labels use Cartouche's words: its Controls section, and its note of a setting an env.txt file sets. The settings in that menu keep nxnative's English names, which it takes from no front end.

As **Play** starts one of nxnative's games, behind the console or in Cartouche's place, Cartouche writes the texts in the language it speaks (its own, from the iPhone's languages: English, French, Spanish or German) in the game's data folder, `Library/Cartouche/GameTexts.plist`, written again at each start. nxnative reads them from its environment as it shows the prompt or the menu, and an env.txt line cannot hold the prompt's five lines. So Cartouche's code in the game's process, which LiveContainerShared loads in every game behind the console and in Cartouche's place ([`launcher/Guest/CartoucheGameTexts.m`](../../launcher/Guest/CartoucheGameTexts.m), [`CartoucheGameTextsEnvironment.m`](../../launcher/Guest/CartoucheGameTextsEnvironment.m)), puts them in the game's environment as the game has finished launching, once nxnative's `main.m` has read the game's env.txt files: a text the player's env.txt or the game's start sets stays theirs. It sets those two variables alone, never another of nxnative's switches, and only in nxnative's games. Cartouche's journal says the texts a game starts with ("<game>: nxnative's texts in fr (DM_CTRL_PROMPT_TEXT, DM_GAME_MENU_TEXT)").

The launcher's tests check the table and the file (`CartoucheGameTextsTests`), the harness that **Play** writes it and that the game's process sets it, without overriding a text already set (`PlayTests`), the Mac's tests that the Mac says the iPhone's words (`MacPlayTests`), and app/tests/test_game_texts.py the rest. None of it has been seen in a real game on an iPhone yet.

**Why.** The prompt that waits for more players and the gear menu are nxnative's, over the game, and the iPhone's players saw them in English while the Mac's saw them in their language (Ad, 26 November 2026, among the ideas kept for the roadmap; 27 November: "Regarde si on peux pas faire 1 ou 2 truc de la roadmap avant de faire une release").
