# 131. The Mac keeps its games' saves in the iPhone's saves folder, and sends its games to the iPhone's games folder, on the player's connections

2026-11-17

With its connections, a paired iPhone tells the Mac the games folder and the saves folder the player chose on it, and when (`CartoucheChosenFolders`, [`CartoucheConnections.swift`](../../launcher/Sources/CartoucheConnections.swift)); of each, the Mac keeps the one chosen last on any iPhone, on the connection that took the place of its own when one did.

When that saves folder is on one of the player's connections, a NAS's shared folder over SMB, an S3 bucket, an FTP or SFTP server or a Google Drive, Cartouche Builder keeps the saves of the games played on the Mac there, through the same connection, by the iPhone's own code with the Mac's guards ([`MacConnectionSaves.swift`](../../builder/mac/Sources/BuilderKit/MacConnectionSaves.swift), [`ConsoleConnectionSaves.swift`](../../builder/mac/Sources/CartoucheConsole/Mac/ConsoleConnectionSaves.swift)), before and after each game, as the iPhone does: a game started meanwhile keeps the saves it found, and saves this Mac kept in step with another folder, unchanged since, give way to the newest copy there. The console's Storage page shows that folder as the iPhone does, and the builder's **iPhone** page shows it in place of its own. When none is, the saves stay where they were: in the builder's folder, or Cartouche's on a share mounted on the Mac.

When the games folder is on one of the connections, the builder sends it each IPA and each Mac app of its own games folder, through the same connection, the newest first, one file at a time ([`ConnectionGames.swift`](../../builder/mac/Sources/BuilderKit/ConnectionGames.swift), [`IPhoneGames.swift`](../../builder/mac/Sources/CartoucheBuilder/IPhoneGames.swift), [`ConsoleConnectionGames.swift`](../../builder/mac/Sources/CartoucheConsole/Mac/ConsoleConnectionGames.swift)): after a reading of the library that changed it, or five minutes after the last look, every half hour, and with **Send now**; never during a batch, a batch that starts letting the file going end and stopping there. What goes is a file the folder lacks, or holds older under the same name. The same name and size there is the same file, so the builder's own games folder on that share sends nothing; a newer file there, another Mac's, stays; a file the player removed there after it went stays removed, until a new build of it. Nothing there is ever removed, and nothing goes to a folder without the room for it, 64 MB to spare, or that the player's account may only read. A Mac app the games folder keeps as it is, on the Mac's own disk, is packed in one file first, as a NAS keeps it (`api mac-pack`), in the builder's folder, and that file is removed once sent. The console's Storage page shows the folder under **This Mac**, how many of the builder's files went, the one going, or why none goes; the builder's **iPhone** page shows it too.

The Mac apps another Mac sent there, of games this Mac has no app of, the console offers as it offers a NAS's, with **Install** on their sheet: the builder fetches the file into its folder, reading on where it stopped when the network drops for a moment, and the engine installs it in the Mac apps folder without recording it as a build of this Mac's (`api mac-install TITLE_ID --from FILE`). It is then made again of each newer file there, unless the game is open or this Mac builds the game itself. The measurements count a file sent (`builder.sent`) and an app installed from there (`builder.macInstalled`, `from: connection`), with the connection's kind alone, never its name, its address or a path.

It amends [decision 125](125.md), where the Mac did not use the connections yet for its games and saves. None of it has been tried on a real Mac or iPhone yet. Amended by [146](146.md): the folders are chosen on the Mac's console too, and go back to the iPhones, the one chosen last winning.

**Why.** Ad asked for one library across their iPhones and Macs (2026-11-13), and for the builds to go to the NAS, in the games folder chosen there (2026-11-17); on 2026-11-17, they chose to have the saves and the games on the iPhone's connections before the version of November 19. Through the iPhone's own code, the Mac reaches every place the iPhone does, S3 and Google Drive included, which a folder mounted in the Finder never was. Removing nothing there, and leaving a newer file there as it is, leaves the player's other Macs' builds and the player's own choices alone; a Mac app packed once for each build, and the same name and size taken for the same file, keep a slow connection from carrying a game twice.
