# 137. A game whose build converts its BC textures for a GPU that reads none is no longer *Not supported* there

2026-11-18

On an iPhone whose GPU cannot read BC-compressed textures, the A16's and older, Cartouche reads the executable of each installed game to tell whether its build converts those textures, as the `no-bc` branch of [mianmuhammadse/nxnative](https://github.com/mianmuhammadse/nxnative/tree/no-bc) does: BC1 to BC3 stored as ASTC 4x4 on the GPU, the others decompressed ([`CartoucheBCConversion.swift`](../../launcher/Sources/CartoucheBCConversion.swift)). It reads the C strings of the game's arm64 executable alone (`__TEXT,__cstring` and the sections of the same type), where nxnative's host, built into the game, has its words: a build converts when they name the conversion's setting, `DM_NO_BC_ASTC`, and neither of nxnative's refusals of such a GPU, at the game's start (`dm/ios/Sources/main.m`) and at its first image (`dm/gfx/nvn/nvn_mtl.m`). A file that is not an arm64 executable, that ends too soon, or whose words say nothing of it converts nothing. The conversion is NVN's alone, the fork's README saying that Vulkan and OpenGL games still need a GPU with BC: a game that nxnative's list says is drawn with anything but NVN or NVN2 (`graphics` in [`catalog/nxnative.json`](../../catalog/nxnative.json), from nxnative's table of games) keeps its warning, whatever its build says.

Such a game's sheet then has its BC requirement met, *Textures converted to ASTC by this game's build*, and its fit is no longer *Not supported* for its GPU: iOS, Increased Memory Limit, its peak and its results decide it, as on another iPhone ([`CartoucheGameFit.swift`](../../launcher/Sources/CartoucheGameFit.swift)). Each answer is kept for the game's bundle with the date of its Info.plist and the date and size of its executable, and read again when they change. The question Cartouche asks before it installs a game on such an iPhone, and the System page's note, stay as they are: they come before Cartouche has a build to read, and say what holds for nxnative's own builds. Each game session's report says, on such an iPhone, whether the game's build converts them (`bcTextures`, `converted` or `unconverted`), and the game sheets count, for a model whose GPU reads none, only the sessions of a build that converts them ([telemetry/README.md](../../telemetry/README.md#game-sheets)). The console of Cartouche Builder reads the same, but a Mac's GPU reads BC textures: nothing changes there. This amends [decision 67](../decisions.md), under which a game's fit on such a GPU was *Not supported* whatever its build. Amended by [145](145.md): a build that converts a Vulkan game's textures, as the fork's does since 22 November, lifts its warning too, and the sheet says *Textures converted for this GPU by this game's build*. Amended by [176](176.md): the question before an install reads the game's build, and one that converts the textures installs without it.

**Why.** A player with an iPhone 15, an A16, asked on Cartouche's Discord on 18 November 2026 for a way to ignore the warning: his fork of nxnative converts the textures, and Metroid Dread and Breath of the Wild run on his iPhone with it. A setting the player turns on would hide the warning from the players whose build does not convert, whom nxnative stops at the game's start; reading what the game's build says instead shows a converted game as it is and keeps the warning of every other, with nothing for the player to set. The setting's name is the fork's alone, and a build of nxnative's own carries its refusals: read together, they tell a converted build from one that only has nxnative's words, and reading the C strings alone keeps the same letters in a game's data, or in a symbol, from saying anything. The executable is mapped, not read, once for each build: a game's is often hundreds of megabytes. The sheets' memory peaks were measured on GPUs that read BC textures; ASTC 4x4 takes twice the memory of BC1, and a decompressed texture four to eight times that of its BC form, so a converted game's peak on an A16 is higher than its sheet says, by our estimate near 3.9 GB for Breath of the Wild where its sheet says 2.8, until the sessions of converted builds measure it on each model. Those sessions alone count there, since nxnative's refusals would otherwise give a model the result *does not run* for a game that a converted build plays on it.
