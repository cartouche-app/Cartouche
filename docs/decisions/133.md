# 133. A game whose shaders nxnative's newest commit splits otherwise than its profile says builds from the commit before nxnative's splitter changed

2026-11-17

nxnative's shader split checks the tables it makes of a game's shaders against those of the game's profile, which were split when the profile was registered ("the split shader tables differ from game profile ...", at the step "shader split"). Cartouche Builder names this failure `tables` ([`causes.py`](../../builder/cartouche_builder/causes.py)), and builds the game again from the parent of the newest commit that changed nxnative's splitter (`dm/gfx/tools/shader_split.py`) since the profile's tables last changed; when that parent splits the game's shaders otherwise too, from the parent of the change before it, and so on through the three newest changes, in the same batch ([`fallback.py`](../../builder/cartouche_builder/fallback.py), `split_back`): alone, once no other game builds, its IPA and its Mac app, or its Mac app alone for a game built for this Mac only. Then the checkout goes back to the commit the batch builds the other games from, which is not marked broken for them, as an app build that fails for every game is (decision 70). The commit comes from nxnative's history, not from the builds this Mac made, so a Mac that never built a game has it too. This amends [decision 70](../decisions.md), whose fallback takes an app build that fails alone, to a commit that built on this Mac.

The game is held there on this Mac (`nxnative.json`, `split`): up to date while nxnative's newest is the commit its split failed at, and tried again at each newer one. A newer one that still splits it otherwise does not build it again from the older commit while its IPA, or its Mac app, is from there or newer with the same files and tools: the game is skipped, in the player's words, and its IPA stays. An older commit that did not build it either is not tried again with the same files; one that failed for the Mac's sake (a full disk, its Xcode) says so, and is tried again at the next batch. With the tables split since the splitter changed, no older commit is tried: the game's files are then not the version the profile registers, or nxnative has to split the profile again, and the player reads both in their words. **Builds** says of a game built that way that it comes from before nxnative changed how it reads shaders, the newest reading this game's otherwise than its profile for now, and the measurements say it beside the older commit (`split`, with `fallback`, on `builder.built` and `builder.macBuilt`).

**Why.** nxnative's 8d62601f (16 November 2026, Welcome Tour's ray tracing) changed how its splitter reads a shader that `main` holds twice, keeping the first copy instead of the last, and split again the tables of Welcome Tour alone. From then on, Mario Kart World's base game stopped there after 12 minutes of shader split, on a player's Mac as in the first build of Cartouche Cloud, and the measurements of 17 November show other games failing at that step since, on Macs that had built them before (Breath of the Wild, Super Mario Odyssey, Wonder, Fortune's Weave). The builder's fallback (decision 70) took only an app build that fails, and only to a commit that built a game on this Mac: most of the Macs that failed had never built that game, and one that built another game since 8d62601f would have gone to a commit that splits as wrongly. At 24e007be, its parent, the splitter makes the profile's tables again, which is why Cartouche Cloud builds from it. The splitter changes often, 28 times between Mario Kart World's tables of 7 November and 8d62601f, the 27 others without harm to it: the newest change is the likeliest cause, the commit before the oldest change since the tables would lose ten days of nxnative for nothing, and going back one change at a time, the three newest at most, keeps the game building when the splitter changes again before nxnative splits its tables again, where the commit before the newest change alone would split them as wrongly. The game built is the one 24e007be builds; only the commits since are missing from it, until nxnative splits the profile's tables again or reads the shaders as before, which its newest commit then builds. The builder does not change nxnative's files or tables (28).
